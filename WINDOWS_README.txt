gpt-auto-register 修改版 · Windows 使用说明
打包日期：2026-10-30

v13 邮箱代理更新：Outlook 的 Microsoft 取 Token、Graph 读信、IMAP 收信均跟随
本次注册任务的代理。单次使用页面填写的代理；批量使用该 worker 实际选中的代理。
支持 http://host:port、socks5://host:port（也支持 socks5h://）及用户名密码认证。
裸 host:port 按 HTTP 处理。密码包含 @、: 等保留字符时，应使用 URL 百分号编码。
SOCKS5 由代理解析目标域名；HTTP 代理必须允许 CONNECT 到邮箱的 993 端口。
https:// 代理不支持 IMAP 连接，会明确报错，请使用 HTTP CONNECT 或 SOCKS5。
代理失败不会自动转直连；留空明确直连，不再隐式读取系统 HTTP_PROXY 等环境代理。
Clash TUN / VPN 等操作系统层路由仍可能接管流量，日志不会宣称实际出口 IP。
瞬时连接、超时及 429/502/503/504 按同一代理有限重试；400/401/403 权限错误
不会用相同请求反复重试，Graph 不可用时仍可尝试 IMAP。更换代理不能补足邮箱权限。
日志显示邮箱连接方式，不打印代理用户名密码或 Microsoft Token。
本版新增 PySocks 依赖，必须更新完整程序；一键启动会自动检测并安装新依赖。
升级前等待所有任务结束、关闭旧程序，备份并迁移 webui\webui.db 后重新启动。

v12 冷却时间更新：全自动批量的「冷却」改为分钟，取消原来的 120 秒输入上限，
支持小数，填 0 表示不等待。旧浏览器中保存的秒数会自动换算为分钟，
例如 120 秒显示为 2 分钟；原有等待时长不变。修正后端把 0 误作 3 秒的问题。
本版同时更新前端页面及后端，请使用完整新包，不要仅替换 auth_flow.py。
先等待任务结束并退出旧程序，再按文末说明迁移数据，启动后刷新页面。
冷却设置在点击「开始」时读取，修改后须停止当前批量并重新开始才能生效。

v11 设备标识一致性修正：warmup 已有 ChatGPT 的 oai-did Cookie 时，获取授权
地址会沿用当前会话中的该值，不再另外生成一个不同的 ext-oai-did。
仅读取 ChatGPT 域根路径下未过期的 Cookie，不重建会话，也不导入其他浏览器
的 Cookie；若同域适用的设备 Cookie 值冲突，会停止并报告 invalid_state。
日志新增「认证设备标识：沿用当前 ChatGPT 会话 Cookie」，不输出 Cookie 值。
此项本地一致性问题已离线复现并修正；尚未证实它就是 Cloudflare 403 的触发
原因，也不保证认证请求不再遇到验证。继续保留 v10 的 [auth_diag] 日志。
已经使用 v10 的用户，可正常退出程序、备份旧 auth_flow.py 后，仅用本包的
auth_flow.py 替换同名文件，再用原启动脚本重启；账号数据继续使用原目录。

v10 诊断版更新：认证请求收到挑战页或失败状态时，新增 [auth_diag] 日志。
记录阶段、HTTP 状态、最终响应域名、响应类型、CF-Ray，以及挑战判定依据。
新增诊断行不记录正文、Cookie、Token、完整认证链接或代理密码；原有日志可能
包含账号凭据，反馈时请只复制 [auth_diag] 行和对应时间，不要直接发送全部日志。
challenge_evidence=cf-mitigated 表示响应头明确标记挑战；html_markers 表示
根据页面特征识别；none 表示没有命中挑战检测。other/missing/invalid 是经过
限制的诊断占位值，不能据此认定服务端返回的原始内容是什么。
本次只补充诊断，保留原来的拒绝处理和自动暂停逻辑，不会自动完成浏览器验证。

本次测试建议：先暂停自动批量，在同一台 Windows 机器的正常浏览器中分别检查
ChatGPT 首页和登录页，再核对代理客户端中浏览器与 Python 的实际域名线路。
程序先做单次测试；若出现 challenge_required，保留 [auth_diag] 行并停止重复尝试。
该行同时显示在页面运行日志及 webui\logs\ 对应的运行日志文件中。
CF-Ray 可供网站支持方关联服务端记录，客户端不能用它直接查出私有安全规则。

v9 更新：复查并补强停止等待。以实际注册线程的结束信号配合数据库结果判断完成，
日志目录或数据库异常导致线程退出时，不会一直卡在「停止中」；无法确认最终结果时
停止继续派发并提示核对本地记录，不把状态不明的账号自动放回池中重试。
修复状态通知顺序，避免旧的「运行中」覆盖「停止中」，概览页同步显示停止状态。
正常注册、120 秒冷却、AT/ST、RT 关闭、2FA 开启及账号池推送格式保持不变。
如果注册线程确实仍在等待网络或验证码，仍需等它结束；停止不等于强制中断。

v8 更新：修复自动批量点击停止后，调度结束但已启动注册线程仍可能继续的问题。
停止只阻止新任务；已开始的取凭证、2FA、后台推送会继续完成。等待期间显示
「停止中，等待当前任务」，不能重新开始，直到所有当前任务结束。
此修复避免停止后重开造成线程重叠，不保证消除 Cloudflare 安全验证。
保留 v7 的完整资料推送、RT 关闭 / 2FA 开启默认值及完整 JSON 保存和导出。

v7 更新：accounts 推送新增已保存的账号密码 password、2FA 长期密钥 totp_secret、
factor ID（totp_factor_id）和注册日志 registration_log。密码保留原样。
registration_log 来自完整注册快照 events 中的结构化 HTTP 事件，不包含终端日志；
历史记录没有这些事件时省略此字段，不发送空数组清除后台已保存日志。
AT 必填，RT 和 ID Token 不发送。默认仍不获取 RT、开启 2FA，正常获取 AT/ST。
本地完整 JSON 继续按原样保存和导出。这些新增字段需要接收端更新后才能保存；
本包不代表线上后台已经部署或已保存新字段，升级后应检查后台实际入库结果。

v6 更新：修复 warmup 报 Impersonating safari18_4_ios is not supported。
Safari 配置统一使用依赖支持的正式名称（例如 safari184_ios），请求前离线验证
客户端配置；不支持时立即报 client_configuration，不再连续重试后误提示代理故障。
warmup 的挑战页或 HTTP 拒绝直接停止并报告 HTTP 状态；缺少 Cookie 的提示不再
断言后续必然 409。保留 v5 的 accounts 推送、完整 JSON、RT 关闭 / 2FA 开启默认值。

v5 更新：账号池推送改用 accounts 数组，携带同一份注册快照中的 AT、邮箱、
设备 ID、ST、完整 Cookie header 和 CSRF；只发送已获取字段。
v7 在此格式上新增密码、2FA 长期密钥、factor ID 和结构化注册日志，详见第五节。
默认仍为不获取 RT、开启 2FA、正常获取 AT/ST。

v4 更新：修复系统 NO_PROXY/no_proxy 环境变量可能覆盖程序显式代理的问题。
设置代理后，注册会话的 HTTP / HTTPS 请求必须交给该代理；代理失败不会自动改为直连。
这不改变 Clash 等代理软件内部的分流规则，也不保证通过远端安全验证。

这是当前 gpt-auto-register 的修改版，不是 aBaiFreeGPT。
包含修改后的程序、已编译前端、Windows 一键启动脚本及源代码。
不含本机测试邮箱、账号凭证、管理密钥、数据库、日志或 Mac 虚拟环境。
Windows 首次启动是一个空库，需要重新导入邮箱并填写后台推送配置。

一、首次准备（只做一次）

1. 使用 Windows 10/11 的 x64 电脑。本包未验证 Windows ARM64 原生环境。
2. 安装 Python 3.13 的 64 位版本；启动器也支持 Python 3.11、3.12 x64。
   官方地址：https://www.python.org/downloads/windows/
   选择 Windows installer (64-bit)，安装时勾选 Add Python to PATH，保留 pip。
   不要选择 embeddable package。本启动器未适配 Python 3.14/3.15。
3. 安装 Node.js 24 LTS 的 Windows x64 版本，保留默认的 PATH 设置。
   官方地址：https://nodejs.org/en/download
   Node 是注册流程的运行依赖；前端已经编译好，不用执行 npm install。
4. 将 ZIP 完整解压到普通可写目录，例如 D:\gpt-auto-register。
   建议使用不含中文的目录，避免部分 Windows 环境的原生依赖文件路径编码问题。
   不要直接在压缩包内部双击运行，也不要只复制启动脚本。

二、一键启动和停止

双击「一键启动.bat」（或 start_windows.bat）。
首次启动会创建本目录的 .venv，并安装 requirements-windows.txt 中的 Python 依赖，
因此首次需要联网访问 Python 包源。以后启动会复用这个环境。
启动成功后自动打开：http://127.0.0.1:8765/
若浏览器没有自动打开，手动复制这个地址到 Edge 或 Chrome。
服务仅监听本机，不需要开放防火墙端口或使用管理员权限。

使用期间保留启动窗口；关闭网页不会停止服务。
停止时先点击网页的「停止」，等待所有当前任务结束、状态显示「未运行」，
再回到启动窗口按 Ctrl+C。显示「停止中」时仍可能正在完成凭证、2FA 或推送。
切换节点建议：停止 → 等待「未运行」且当前任务全部结束 → 换节点/IP → 重新开始。
并发 1 时，120 秒冷却是在上一轮完整结束后才开始，下一轮会创建新的注册会话；
冷却期内切换节点通常不会修改已完成的上一轮，但切换不能与下一轮请求重叠。
冷却时间不是 Cloudflare 的免验证时限，换节点后仍可能遇到安全验证。
重新启动不会清空已经导入的邮箱和注册结果。
以后如果移动了整个程序目录，删除移动后的 .venv 文件夹，再运行启动脚本重建环境；
不要删除 webui\webui.db。

三、导入 Outlook 邮箱

1. 打开左侧「邮箱配置」，确认邮箱来源为 Outlook；如修改过来源，保存配置。
2. 打开「导入邮箱」，选择 Outlook，把四段信息粘贴进去，每行一个邮箱：

   邮箱地址----邮箱密码----Microsoft客户端ID----Microsoft邮箱RefreshToken

   示例（占位内容，不能用于真实登录）：
   demo@example.com----MAIL_PASSWORD----CLIENT_ID----MICROSOFT_MAIL_REFRESH_TOKEN

3. 点击「导入」，再到「邮箱列表」检查导入结果。

这里第四段是 Microsoft 邮箱的刷新令牌，用于收邮件验证码；
页面里的「获取 RT」开关控制的是注册账号的 RT，两者不是同一个令牌。
关闭「获取 RT」不代表导入邮箱可以省略第四段。

四、注册和查看凭证

1. 先到「单次注册」选一个已导入邮箱，或者留空自动选取可用邮箱。
2. 默认设置已经改为：AT 正常获取、ST 正常获取、RT 关闭、2FA 开启。
   RT 和 2FA 是独立开关，可以分别调整；网页会保留你之后的选择。
3. 如果需要代理，填写 Windows 电脑上实际可用的代理地址；无需代理则留空。
   127.0.0.1 指当前 Windows 电脑，不能沿用另一台 Mac 上的本机代理端口。
   本地 Clash 的 HTTP / SOCKS 地址必须使用它实际监听的端口。
   全自动任务优先使用代理池，池为空时才用单次注册页的单代理。
   修改代理后，已启动的自动任务需要停止后重新开始，暂停/恢复不会重载代理。
4. 点击「开始注册」，查看页面日志及结果。
   邮件到达较慢时，可将 OTP 等待秒数设置为 120～180 后再测试。
5. 「注册结果」中可以查看/复制/导出凭证，查看 2FA 绑定结果并备份密钥。
   开启 2FA 只代表请求绑定，是否绑定成功应以该账号结果和日志为准。
6. 「全自动批量」也提供 RT、2FA 独立开关。首次验证建议并发 1、目标数 1。

完整注册 JSON（v3 新增）

新注册的账号会在本地数据库中保存注册时的完整结果快照，包含 program、mode、
credentials、cookies、events、2FA 绑定结果及实际观测到的阶段状态。
credentials 保留设备 ID、CSRF 和完整会话 Cookie 等已获取字段。
HTTP events 记录方法、去除查询参数的路由、响应状态、耗时等，不包含请求正文、
验证码或管理员密钥；不是把所有 HTTP 明文日志原样打包。

在「注册结果」可以直接导出某一个账号的完整 JSON，或者勾选账号后批量导出。
未勾选时可导出全部；单号文件是一个 JSON 对象，多号文件是 JSON 对象数组。
凭证弹窗可按需查看、复制完整注册 JSON；导出本身不会上传或删除账号。
后续手工修改当前密码、2FA 密钥不会改写注册时快照，应区分当前凭证与历史快照。

老版本记录如果没有完整快照，只能由已有字段重建；会标记 source=legacy_database、
capture_complete=false，说明缺少原始事件/Cookie。不会自动重新登录补采。
开启完整保存不改变 RT/2FA 选项：默认仍不取 RT、开启 2FA、正常获取 AT/ST。
完整 JSON 含账号凭证和 2FA 密钥，请与数据库一样自行妥善保管。

五、注册成功后推送到你的后台号池

打开「后台推送」，填写账号池配置：
  接口 URL：https://pool.example.com/api/accounts
  后台管理密钥：填写你自己的后台管理密钥（本包未携带旧密钥）
  超时：默认 40 秒

先「保存配置」，再「测试账号池连接」。连接测试只读取状态，不上传账号。
测试时按钮会显示已等待的秒数，按钮下方会保留成功或失败结果及耗时。
如果 URL、管理密钥或超时尚未保存，页面会提醒先保存，避免误测旧配置。

自动推送：打开「注册成功后自动推送到账号池」并保存。
手动推送：在「注册结果」勾选账号，点击「推送到后台」，不要求开启自动推送。
手动每次最多 20 个；推送期间不要重复点击。

接口为 POST /api/accounts，使用 Authorization: Bearer 管理密钥，
Content-Type: application/json，请求体示例如下（均为占位值）：

{
  "accounts": [
    {
      "credentials": {
        "email": "user@example.invalid",
        "access_token": "AT",
        "device_id": "注册时的设备ID",
        "session_token": "ST",
        "cookie_header": "注册会话的完整Cookie请求头",
        "csrf_token": "CSRF",
        "password": "ACCOUNT_PASSWORD",
        "totp_secret": "TOTP_LONG_TERM_SECRET",
        "totp_factor_id": "TOTP_FACTOR_ID"
      },
      "registration_log": [
        {
          "elapsed_s": 1.2,
          "event": "http",
          "source": "registration",
          "method": "GET",
          "route": "chatgpt.com/api/auth/session",
          "status": 200,
          "error_code": "",
          "challenge": false,
          "deactivated": false
        }
      ]
    }
  ]
}

AT 必填，其余字段有值才发送。自动和手动推送使用相同格式，每个请求一个账号。
密码保留保存时的原样值；2FA 发送长期密钥 totp_secret 和 factor ID（如已保存）。
RT、ID Token 不发送，也无需打开「获取 RT」。本地完整 JSON 仍按原样保存和导出。
registration_log 使用完整注册快照的 events 结构化 HTTP 事件，不读取或发送终端日志。
历史账号没有原始 events 时省略 registration_log，不发送 [] 清除后台已有日志。
接收端必须更新后才会保存新增的密码、2FA 和日志字段；旧版后台可能忽略这些字段。
连接测试成功只表示地址与管理员鉴权可用，不代表新增字段已入库。
网页 session_id 当前没有独立采集，不使用 2FA enrollment 的 session_id 代替。
新账号整组使用注册快照，避免将新 AT 与旧设备/Cookie 拼接；
当前 AT 与快照不一致或仅保留早前快照时会停止推送并提示原因。
旧账号没有完整快照时，仅推送同一条数据库记录里已有的字段；
未保存的设备、ST、Cookie 或 CSRF 不会自动补齐，也不会自动重新登录。
已经推送过的账号，如果本地保存了这些字段，可在接收端更新后手动再次推送补传。
后台启用诊断暂存或账号处于隔离时可能拒绝完整格式（409），请检查后台状态；
程序不会自动改回 tokens 格式，也不会对结果未知的请求自动重试。
因此不需要打开 RT，也不需要开启下面的 CPA / SUB2API 导出。
推送失败仍保留本地注册结果；超时或结果未知时先检查后台，再决定是否重试。
显示「暂存」表示后台已接收，但还没有进入正式号池；请到后台处理对应状态。

六、数据保存和备份

webui\webui.db：邮箱、账号凭证、2FA、后台配置等数据。
webui\logs\：运行日志。
.venv\：自动创建的 Python 环境，不是账号数据。

迁移或备份：先正常停止程序，再复制整个 webui 数据目录，或至少复制
webui.db 及同目录中仍存在的 webui.db-wal、webui.db-shm 文件。
这些数据包含凭证，应自行保管。浏览器保存的表单开关不包含在数据库备份中。

七、常见问题

Impersonating ... is not supported / client_configuration：这是本地 HTTP 客户端
配置与依赖不兼容，请先更新至本诊断版；不是这一步遭到远端 Cloudflare 拒绝。
若新版仍报该错，停止程序，删除程序目录中的 .venv，再双击一键启动重建依赖。
不要删除 webui\webui.db；不要只在系统 Python 中升级依赖（程序使用独立 .venv）。
旧版 safari18_4_ios 在 curl_cffi 0.16.3 的请求准备层会失败，v6 已改为 safari184_ios。
中文目录可能另行引起路径编码/证书文件错误；搬到英文目录不能修复旧版配置名。

提示找不到 Python / Node：按第一节安装指定版本，安装后重新双击启动脚本。
依赖下载失败：检查该 Windows 电脑能否访问 PyPI，再重新启动；不要删除数据库。
8765 端口被占用：先检查是否已经打开过程序，或关闭占用端口的其他服务后再启动。
打不开页面：保留启动窗口并查看最后的错误，确认地址是 http 而不是 https。
邮箱验证码超时：检查邮箱四段信息是否有效、收信链路及网络；适当延长 OTP 等待。
403 / challenge_required / invalid_state：属于远端访问或认证流程问题，
打包和一键启动本身不保证解决。根据错误检查网络和账号状态，避免连续重复提交。
日志的 cloudflare.com IP 只代表该检测站点出口；Clash 规则可能使认证域名走另一条路线。
请在 Clash 的连接记录中分别检查 cloudflare.com、chatgpt.com、auth.openai.com
对应的规则与出口；浏览器能打开首页不能证明程序的认证请求走同一路线。
当前程序为协议流程，没有浏览器手动验证后继续本轮任务的接管功能；
在另一个浏览器通过验证不会自动接续已停止的程序会话。
遇到 challenge_required 时应停止自动尝试，先使用正常浏览器检查网络与服务访问情况。
该错误本身不是账号停用结论，也不能据此断定只换 IP 就能解决。
后台推送失败：先保存配置并测试连接；401/403 检查管理密钥和权限；
服务暂不可用时稍后再检查。注册成功和入池成功是两个独立结果。

验证范围

本包已包含已构建的前端。打包时会验证 Python 测试、ZIP 文件完整性、
Windows x64 Python 依赖轮子可用性，并从解压后的副本启动服务检查页面/API。
制作环境是 macOS，没有在真实 Windows 电脑执行 BAT 或重新注册真实账号；
Windows 上的 Python/Node 安装、网络和外部服务状态仍需要在目标电脑确认。

从旧版升级

从旧版升级时，先暂停批量任务，等所有已启动任务显示完成或失败，
再点击停止；随后在旧启动窗口按 Ctrl+C，等待程序完全退出。
备份旧程序的 webui 数据目录；将新 ZIP 解压到另一个目录。
把旧 webui\webui.db 复制到新目录的 webui 下；若旧目录仍存在
webui.db-wal、webui.db-shm，也一同复制，保留原件备份。
不要复制旧 .venv；双击新目录的「一键启动.bat」创建或使用新环境。
新包不含账号数据库或管理密钥，已有配置随复制的数据库迁移。
v7 会在账号池推送时发送本地已保存的密码、2FA 长期密钥、factor ID 和结构化事件。
恢复自动推送或手动补传前，先确认账号池接收端已部署支持这些新增字段的版本。
如果旧库已开启自动推送，该开关会随数据库迁移；需要等待后台更新时，请先关闭自动推送并保存。
已有账号不会因升级自动补传；接收端更新后，可在「注册结果」选中账号再次推送。
缺失的历史事件不会补造，也不会以空数组覆盖后台日志；本地完整 JSON 保留原样。
